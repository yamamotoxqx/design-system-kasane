はじめに / Kasane とは

Kasane とは

Kasane(かさね)は、Webサイトと Webアプリのためのデザインシステムです。面を重ねて情報を区切り、アクセントの色を9色から選べます。

名前の由来

「かさね」には2つの意味があります。1つは、背景・カード・中の面と、面を重ねて画面を組み立てること。もう1つは、色の組み合わせを楽しむ「襲(かさね)の色目」です。パレットの名前も、山吹、藤、藍など日本の色の名前から取っています。

特徴

枠も影も使わない

カードやリストは、面の色の差だけで区切ります。枠を持つのは入力欄だけです。

9色から選べる

アクセントの色を変えても、文字の読みやすさは同じ基準を守ります。

CSSだけで使える

トークンと部品は1つのCSSファイルで、URLから読み込めます。ビルドや JavaScript のライブラリは要りません。

はじめに / 使い始める

使い始める

CSSを読み込み、<html> に色の名前を付けるだけで使えます。ファイルはURLで配信しているので、手元に置く必要はありません。

1. CSSと書体を読み込む

kasane.css に、色のトークン(9色)、書体・角丸・余白のトークン、部品のスタイルがすべて入っています。軽い縮小版の kasane.min.css もあります。

HTML
<link href="https://fonts.googleapis.com/css2?family=Zen+Maru+Gothic:wght@900&family=Inter:wght@400;500;600;700&display=swap" rel="stylesheet">
<link rel="stylesheet" href="https://kasane.y-n0.de/v1/fonts/line-seed-jp.css">
<link rel="stylesheet" href="https://kasane.y-n0.de/v1/kasane.min.css">

URLの v1 は版の番号です。見た目が大きく変わる更新は新しい版として出すので、同じURLを使っている限り、見た目が急に変わることはありません。

2. アクセントの色を選ぶ

data-accent にパレットの名前を書きます。書かなければ山吹になります。使える名前は カラー のページにあります。

HTML
<html lang="ja" data-accent="ai">

3. ライトとダークを切り替える

何も指定しなければ、端末の設定(prefers-color-scheme)に従います。利用者が切り替えられるようにするには、data-theme に light か dark を書きます。このサイトのページ下部にある切り替えも、この方法です。

JavaScript
const root = document.documentElement;

// いまダークかどうか(指定がなければ端末の設定)
function isDark() {
  const t = root.dataset.theme;
  return t ? t === "dark" : matchMedia("(prefers-color-scheme: dark)").matches;
}

// "light" か "dark" に切り替えて保存する
function setTheme(theme) {
  root.dataset.theme = theme;
  try { localStorage.setItem("kasane-theme", theme); } catch (e) {}
}
HTML
<div class="k-seg" role="group" aria-label="テーマ">
  <button type="button" aria-pressed="true" onclick="setTheme('light')">ライト</button>
  <button type="button" aria-pressed="false" onclick="setTheme('dark')">ダーク</button>
</div>

4. 選んだ色を保存する

色やテーマを保存している場合は、<head> の先頭で、CSSより前に適用します。こうすると、ページを開いた瞬間に別の色が見えるちらつきを防げます。

HTML
<head>
  <script>
    try {
      var a = localStorage.getItem("kasane-accent");
      var t = localStorage.getItem("kasane-theme");
      if (a) document.documentElement.dataset.accent = a;
      if (t) document.documentElement.dataset.theme = t;
    } catch (e) {}
  </script>
  <link rel="stylesheet" href="https://kasane.y-n0.de/v1/kasane.min.css">
</head>

原則 / デザイン原則

デザイン原則

どの色を選んでも同じ使い心地になるように、5つの原則を決めています。

5つの原則

1面を重ねて区切る

背景、カード、中の面と、内側に入るほど面の色を一段ずつ変えます。枠を持つのは入力欄だけです。入力欄は「書き込める場所」だと一目で分かる必要があるためです。

2色は選べる、読みやすさは変えない

色は必ずトークンで指定します。塗りには --accent、その上の文字には --on-accent、アクセント色の文字やリンクには --accent-ink を使います。こうすると、どのパレットでも文字は4.5:1以上のコントラストになります。

3色だけで伝えない

成功は緑、エラーは赤で固定していますが、色の見え方は人や画面によって変わります。状態にはアイコンと文字を必ず添えます。チェックは印、スイッチはつまみの位置でも状態が分かるようにします。

4やわらかく、はっきり

カードは28px、中の面は18px、入力欄は14pxの角丸にし、ボタンは丸薬型にします。押せる場所は高さ44px以上を基本にし、キーボードで操作したときはフォーカスのリングを必ず表示します。

5書体は役割で分ける

基本の書体は LINE Seed JP です。例外は2つだけで、ページのタイトルと章の見出しは Zen Maru Gothic の極太、桁をそろえたい数字は Inter の等幅数字にします。くわしくは タイポグラフィ にあります。

document.querySelectorAll('[role="tablist"]').forEach((list) => {
  const tabs = [...list.querySelectorAll('[role="tab"]')];
  const select = (tab) => tabs.forEach((t) => {
    const on = t === tab;
    t.setAttribute("aria-selected", String(on));
    t.tabIndex = on ? 0 : -1;
    document.getElementById(t.getAttribute("aria-controls")).hidden = !on;
  });
  tabs.forEach((tab, i) => {
    tab.addEventListener("click", () => select(tab));
    tab.addEventListener("keydown", (e) => {
      const d = e.key === "ArrowRight" ? 1 : e.key === "ArrowLeft" ? -1 : 0;
      if (!d) return;
      const next = tabs[(i + d + tabs.length) % tabs.length];
      select(next); next.focus();
    });
  });
});

AI と使う

Claude Code や Codex などの AI にUIを作ってもらうときに、Kasane のルールを守ってもらう方法です。ファイルを手元に置かなくても、URLを伝えるだけで使えます。

AI に読ませるもの

AI には、このドキュメントサイトではなく、仕様書の kasane.md を読ませます。動きのあるページや大きなファイルは、AI がうまく読み取れないためです。仕様書には、ルールとその理由、全トークン、全部品の HTML、Kasane にない部品の作り方、作業後のチェックリストが入っています。

ファイル内容
https://kasane.y-n0.de/v1/kasane.md仕様書(AI と人が読む)
https://kasane.y-n0.de/v1/kasane.min.cssすべてのトークンと部品の CSS
https://kasane.y-n0.de/v1/tokens.jsonトークンの値(W3C Design Tokens 形式)
llms.txtAI に仕様書の場所を知らせる案内(サイトの一番上に置く)

Claude Code で使う

プロジェクトの CLAUDE.md に、次の内容を書きます。作業のたびに自動で読み込まれます。

Markdown
## UI

UIを作る・変更するときは、作業の前に次の仕様書を最後まで読み、そのルールに従うこと。
https://kasane.y-n0.de/v1/kasane.md

CSSは次を読み込む。
https://kasane.y-n0.de/v1/kasane.min.css

作業の最後に、仕様書の「作業の最後に確かめること」をすべて確かめること。

URLを読むたびに許可を求められる場合は、配信先のドメインを Claude Code の設定で許可しておくと、聞かれなくなります。

Codex で使う

プロジェクトの AGENTS.md に、上と同じ内容を書きます。Codex をネットにつながらない設定で使っているとURLを読めないので、その場合は kasane.md をリポジトリに置き、そのファイルを読むように書きます。

ほかの AI で使う

チャットで使う場合は、kasane.md の内容を貼るか、ファイルとして添付します。プロジェクトの指示に入れておくと、毎回貼る必要がなくなります。

自動でチェックする

AI は長い指示の一部を読み落とすことがあります。kasane-lint を入れると、ルールの多くを機械的に確かめられます。CSS は Stylelint、HTML は kasane-check が見ます。CSSと同じ配信先から入れられ、GitHub のアカウントは要りません。

bash
npm install --save-dev stylelint https://kasane.y-n0.de/v1/kasane-lint-1.1.0.tgz

プロジェクトに .stylelintrc.json を作ります。

JSON
{
  "extends": ["kasane-lint/stylelint"]
}
bash
npx stylelint "src/**/*.css"
npx kasane-check "src/**/*.html"

同じパッケージに、画像を軽くして SSIM を確かめる kasane-image と、Lighthouse の最低点を確かめる kasane-lighthouse も入っています。使い方は パフォーマンス にあります。

URLのファイル名には版の番号が入っています。ルールを更新するときは新しい番号のファイルを出すので、入れたものが勝手に変わることはありません。

AI に自分で直してもらうには、CLAUDE.md や AGENTS.md に次の1行を足します。

Markdown
作業の最後に npx stylelint "src/**/*.css" と npx kasane-check "src/**/*.html" を実行し、出たものをすべて直すこと。
画像は npx kasane-image で軽くしてから使うこと。
画面ができたら npx kasane-lighthouse で評価し、最低点に届くまで直すこと。

理由があってルールから外れる所には、data-kasane-ignore を付けると、その要素と中身を検査から外せます。ルール名を書くと、そのルールだけを外せます。

HTML
<section data-kasane-ignore="one-primary">…</section>

React などで HTML を JavaScript の中に書いている場合は、ビルドして書き出した HTML(dist/**/*.html など)を検査します。

機械で見つけられないこと(見た目のバランスや、文章の書き方など)は、仕様書のチェックリストと、画面を撮っての見直しで確かめます。

画面を撮って確かめる

スクリーンショットを撮れる AI(Playwright やブラウザを操作できるもの)には、作った画面をライト・ダーク、パソコン・スマートフォンの幅で撮って見直すよう、仕様書で指示しています。文字の切れや重なり、読みにくい色の組み合わせ、部品の大きさのばらつきなど、ルールでは見つけにくい崩れを拾えます。撮れない環境では、撮れなかったことを報告するよう書いてあります。

  • 1文を短くする1つの文には、1つのことだけを書きます。

動きは短く、控えめにします。画面が変わったことに気づけて、操作を待たせない長さにします。

ページを切り替える

このサイトのページ切り替えも、同じ動きです。前のページは動かさずに消し、次のページだけを浮かび上がらせます。両方を動かすと、切り替えのたびに待つ時間が長くなるためです。

CSS
.page:not([hidden]) { animation: k-enter var(--motion-slow) var(--ease-out); }
@media (prefers-reduced-motion: reduce) { .page:not([hidden]) { animation: none; } }
JavaScript
// hidden を付け外しすると、表示のたびに動きが最初から再生されます
function showPage(id) {
  document.querySelectorAll(".page").forEach((p) => { p.hidden = p.dataset.page !== id; });
  window.scrollTo(0, 0);
}

開く・閉じる

ダイアログは、背景をふわっと暗くし、本体を下から浮かび上がらせます。閉じるときは動かさず、すぐに消します。

CSS
.k-scrim  { animation: k-fade var(--motion-base); }
.k-dialog { animation: k-enter var(--motion-base) var(--ease-out); }

このメモを削除しますか?

これは動きの見本です。どちらを押しても、何も削除されません。

操作に反応する

ボタンは、押すと1pxだけ沈みます。スイッチは、つまみが150msで動きます。タブや2択の切り替えでは、選択中の背景が220msで横へ動きます。押した瞬間に反応が返ることを優先して、短くしています。

HTML
<button class="k-btn k-btn-primary" type="button">押してみる</button>
<label class="k-switch">
  <input type="checkbox" checked>
  <span class="k-switch-track" aria-hidden="true"></span>
  切り替えてみる
</label>
<div class="k-seg" role="group" aria-label="表示">
  <button type="button" aria-pressed="true" data-seg-demo>週</button>
  <button type="button" aria-pressed="false" data-seg-demo>月</button>
  <button type="button" aria-pressed="false" data-seg-demo>年</button>
</div>
CSS
.k-btn { transition: background-color var(--motion-fast), transform var(--motion-fast); }
.k-btn:active { transform: translateY(1px); }
.k-switch-track::after { transition: transform var(--motion-fast); }

動きを減らす設定

端末で「視差効果を減らす」が有効なときは、すべての動きを止めます。動きがなくても、内容と状態はすべて分かるようにします。

CSS
@media (prefers-reduced-motion: reduce) {
  .k-enter, .k-scrim, .k-dialog { animation: none; }
  .k-btn, .k-switch-track, .k-switch-track::after { transition: none; }
}

使い方

  • 450msより長くしない長い動きは、操作のたびに待たされる感じになります。
  • 消えるときは動かさない閉じる操作は、すぐに終わらせます。

CSS

CSS
/* Motion: short and quiet */
:root { --motion-fast: 150ms; --motion-base: 220ms; --motion-slow: 450ms; --ease-out: cubic-bezier(.2, .7, .3, 1); }
@keyframes k-enter { from { opacity: 0; transform: translateY(16px); } }
@keyframes k-fade { from { opacity: 0; } }
.k-enter { animation: k-enter var(--motion-slow) var(--ease-out); }
@media (prefers-reduced-motion: reduce) { .k-enter { animation: none; } }

原則 / アクセシビリティ

アクセシビリティ

誰でも、どんな状況でも、迷わず読めて、操作できる状態を目指します。色を選べる Kasane では、どの色を選んでも同じように使えることが土台です。

目指すこと

使いにくさは、障害のある人だけのものではありません。年齢を重ねたとき、けがをしたとき、眼鏡を忘れたとき、外の光が強いとき、片手がふさがっているとき。状況が変わると、誰でも同じ画面が使いにくくなります。

アクセシビリティを高めると、そうした状況でも使えるようになり、ふだんの使いやすさも上がります。全員にとって完ぺきな形は作れなくても、別の見せ方や操作の手段を用意すれば、使える人は確実に増えます。

4つの使いにくさ

どんな使いにくさがあるかを知ることが、最初の一歩です。Kasane の部品は、次の点に気をつけて作っています。

使いにくさたとえばKasane で気をつけていること
見えにくい文字がぼやける、外の光で画面が読めない、色の区別がつきにくい、画面が見えない全パレットで文字のコントラスト 4.5:1 以上。色だけで伝えない。拡大しても崩れない。スクリーンリーダーで読める
聞こえにくい音を出せない場所にいる、耳が聞こえにくい音だけで知らせない。動画には字幕を付ける
操作しにくい手がふるえる、片手しか使えない、マウスを使えない押せる場所は高さ44px以上。キーボードだけで操作できる。複雑な操作に頼らない
わかりにくい長い文が読みにくい、アイコンの意味がわからない、動きに気を取られる短くやさしい文。アイコンに文字を添える。動きは控えめで、止められる

基準

WCAG 2.2 の AA を目安にします。Kasane の部品と仕様書は、このうち見た目と部品の作りで守れるものを、あらかじめ満たすように作っています。

コントラスト

9色すべてで、ライトとダークの両方がこの基準を満たすことを、パレットを作るときに自動で検査しています。

対象使うトークン基準
本文の文字--ink、--muted面に対して 4.5:1 以上
主ボタンの上の文字--on-accent--accent に対して 4.5:1 以上
アクセント色の文字・リンク--accent-ink面と --accent-soft に対して 4.5:1 以上
状態の文字--ok、--danger、--info対応する -soft の面に対して 4.5:1 以上
入力欄の枠、スイッチのオフ--line--surface に対して 3:1 以上
フォーカスのリング--focus面に対して 3:1 以上

色だけで伝えない

山吹や青磁など明るいパレットでは、ライトのときに --accent の塗りと面の差が 3:1 に届きません。「選ばれている」「オンになっている」を塗りの色だけで伝えず、チェックの印、スイッチのつまみの位置、文字などを組み合わせます。

キーボードとフォーカス

操作できる部品はすべて、Tab キーで移動でき、Enter やスペースで操作できるようにします。フォーカスが当たったときは --focus の3pxのリングを表示し、消しません。マウスを乗せたときだけ見える情報は、フォーカスしたときにも見せます。

CSS
:focus-visible { outline: 3px solid var(--focus); outline-offset: 2px; }

スクリーンリーダー

  • 入力欄にはラベル<label> で囲むか、for で結びます。
  • 文字のないボタンには名前アイコンだけのボタンには aria-label を付けます。
  • 画像には説明alt に内容を書きます。飾りの画像は alt="" にします。
  • あとから出る知らせは読み上げるトーストには role="status" を付けます。
  • 見出しは順番どおりにh1、h2、h3 の順に使い、段を飛ばしません。

押せる場所の大きさ

ボタンや選択肢は、高さ44px以上を基本にします。小さいボタン(.k-btn-sm)でも36pxです。押せる場所どうしは、間を8px以上あけます。

動きを減らす設定

端末で「視差効果を減らす」が有効なときは、Kasane の動きはすべて止まります。動きがなくても、内容と状態はすべて分かるようにします。

CSS
@media (prefers-reduced-motion: reduce) {
  .k-enter, .k-dialog { animation: none; }
}

原則 / パフォーマンス

パフォーマンス

表示が速く、動きが安定していて、思わぬ動きがない状態を目指します。読みたいものがすぐに見えて、触ったらすぐに反応することは、それだけで使いやすさです。

目指す状態

  • すぐに見える読みたい内容や大事な部品が、できるだけ早く表示される。
  • すぐに反応するスクロールやタップに、遅れずに応える。
  • ずれない読み込みの途中で、部品が動いたり消えたりしない。

フォント

LINE Seed JP は、文字の範囲ごとに細かく分けて配信しているので、ページで使う文字の分だけが読み込まれます。フォントの CSS は表示を止めないように読み込み、読み込みが終わるまではいつもの書体で表示します。

HTML
<link rel="stylesheet" href="https://kasane.y-n0.de/v1/fonts/line-seed-jp.css" media="print" onload="this.media='all'">
<noscript><link rel="stylesheet" href="https://kasane.y-n0.de/v1/fonts/line-seed-jp.css"></noscript>

画面のずれを防ぐ

  • 大きさを先に決める画像や埋め込みには width と height を書き、読み込む前から場所を空けておきます。
  • 読み込み中も同じ大きさ読み込み中、0件、失敗したときも、同じ大きさの場所を使います。
  • あとから差し込まない読み込みが終わってから、上に部品を足しません。ログインの状態で部品を消さず、同じ大きさで入れ替えます。

CSS と JavaScript

  • 縮小版を使う本番では kasane.min.css(約 21 KB)を読み込みます。
  • 表示を止めないJavaScript には defer を付けます。大きなライブラリは、本当に必要なときだけ使います。
  • 長い処理を分ける重い処理は細かく分けて、操作への反応を止めないようにします。
